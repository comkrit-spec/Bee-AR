## ขั้นที่ 1: ตั้งฐานข้อมูลบน Google Apps Script

1. สร้าง Google Sheet ใหม่ (หรือใช้ไฟล์เดิม) แล้วไปที่ **ส่วนขยาย > Apps Script**
2. ลบโค้ดเดิมใน `Code.gs` แล้ววางโค้ดจาก `Code.gs` ทั้งไฟล์ กดบันทึก
3. (แนะนำ) ไปที่ **Project Settings** (ไอคอนฟันเฟือง) ตั้ง **Time zone** เป็น `(GMT+07:00) Bangkok`
4. เลือกฟังก์ชัน `setup` ที่แถบด้านบน แล้วกด **Run** หนึ่งครั้ง
   กดอนุญาตสิทธิ์ (Sheet, Drive) ระบบจะสร้างชีตชื่อ **Records** และโฟลเดอร์เก็บรูปใน Drive
5. กด **Deploy > New deployment** เลือกประเภท **Web app**
   - Execute as: **Me**
   - Who has access: **Anyone**
6. คัดลอก **Web app URL** ที่ลงท้ายด้วย `/exec`
7. ทดสอบโดยเปิด URL นั้นในเบราว์เซอร์ ต้องเห็น `{"status":"ok","message":"API ระบบหน้างานพร้อมใช้งาน",...}`

> **อัปเดตโค้ด Apps Script ภายหลัง:** ใช้ **Deploy > Manage deployments > Edit (ไอคอนดินสอ) > Version: New version**
> URL จะเหมือนเดิม ไม่ต้องแก้หน้าเว็บ (ถ้ากด *New deployment* จะได้ URL ใหม่)

### ตั้งค่าเสริม (ไม่บังคับ)

ไปที่ **Project Settings > Script properties > Add script property**

| Property | ใช้ทำอะไร |
|---|---|
| `ADMIN_PINS` | บัญชีผู้ดูแลหลายคน บรรทัดละคน `ชื่อ:PIN:admin` หรือ `ชื่อ:PIN:editor` (ตรวจที่เซิร์ฟเวอร์ และบันทึกชื่อผู้แก้/ลบ) ดู `ADMIN.md` |
| `ADMIN_PIN` | (แบบเก่า) PIN รหัสเดียว ยังใช้ได้ |
| `ADMIN_EMAILS` | (ทางเลือก) อีเมลผู้ดูแลสำหรับโหมดบัญชีองค์กร ไม่ต้องใช้ PIN ดู `ADMIN.md` ข้อ 9 |
| `LINE_CHANNEL_TOKEN` | Channel access token ของ LINE Messaging API สำหรับส่งสรุปรายวัน |
| `LINE_REGISTER_CODE` | รหัสลับสำหรับคำสั่ง `ลงทะเบียน <รหัส>` ในกลุ่ม LINE |

## ผู้ดูแลระบบ

ระบบมี **ศูนย์ผู้ดูแล** ในแอป (แท็บ "เครื่องมือ") สำหรับดูสถานะระบบ สำรองข้อมูล ตั้งค่ากลางให้ทุกเครื่อง จัดการรายชื่อ Job ดูประวัติการแก้ไข/ลบ และกู้คืนรายการที่ลบ ลบรายการ = ย้ายไปถังขยะ (กู้คืนได้) และบันทึกชื่อผู้ทำทุกครั้ง

**ก่อนใช้งานจริงให้ทำ 3 อย่าง:** (1) ตั้ง `ADMIN_PINS` (2) รัน `setup` และ `setupMaintenanceTrigger` ใน Apps Script (3) ให้ผู้ดูแลอย่างน้อย 2 คนเป็น Editor ของไฟล์ Sheet

รายละเอียดทั้งหมด (สิทธิ์ แท็บ Config รายชื่อหลัก ถังขยะ สำรองข้อมูล รับมอบระบบ โหมดบัญชีองค์กร ขั้นตอนปล่อยเวอร์ชัน แก้ปัญหา PDPA) อยู่ใน **`ADMIN.md`** และประวัติเวอร์ชันอยู่ใน **`CHANGELOG.md`**

## เลือกส่วนของแบบฟอร์มที่แสดง

หน้าแอปแบ่งเป็น 5 ส่วน: ข้อมูลเบื้องต้น, **สถานที่**, กำลังพล, เวลา (Activity), รูปถ่าย
เปิด/ปิดได้ที่ **ตั้งค่า (ไอคอนฟันเฟือง) > ส่วนของแบบฟอร์มที่แสดง** ส่วน "ข้อมูลเบื้องต้น" ปิดไม่ได้ เพราะมีช่องบังคับกรอก

- การตั้งค่านี้มีผลเฉพาะเครื่องนั้น (ถ้าตั้ง PIN ไว้ ต้องใส่ PIN ก่อนเข้าหน้าตั้งค่า)
- ปิดส่วนที่มีข้อมูลค้างอยู่ ระบบจะถามยืนยันก่อน เพราะข้อมูลในส่วนนั้นจะถูกล้าง
- ส่วนที่ปิดจะไม่ถูกส่งเข้า Sheet (เซลล์ว่าง)
- ขณะ**แก้ไขรายการเดิม** ระบบจะแสดงทุกส่วนชั่วคราว เพื่อไม่ให้ข้อมูลของส่วนที่ซ่อนถูกทับเป็นค่าว่าง
- ถ้าต้องการกำหนดค่าเริ่มต้นให้ทุกเครื่อง แก้ `DEFAULT_SECTIONS` ใน `config.js` เช่น `photos: false`

### คอลัมน์ "สถานที่" ใน Sheet

ชีต **Records** มีคอลัมน์ `location` เพิ่มขึ้น ถ้าใช้ชีตเดิมอยู่ ระบบจะเติมคอลัมน์นี้ให้เองที่ท้ายตารางเมื่อรันโค้ดใหม่ โดยไม่แตะข้อมูลเดิม
ไฟล์ CSV สำหรับนำเข้าก็เพิ่มคอลัมน์ที่ 19 "สถานที่" (ไม่บังคับ ไฟล์ Template เก่าที่มี 18 คอลัมน์ยังใช้ได้)

## จำ URL ทันที และตั้งค่าเครื่องใหม่

- **จำทันที:** วาง URL ของ Apps Script ลงช่องตั้งค่า ระบบจะจำไว้ในเครื่องทันทีที่รูปแบบถูกต้อง ไม่ต้องกดบันทึก และทดสอบการเชื่อมต่อให้เลย ครั้งหน้าเปิดแอปใช้งานได้ทันที
- **เครื่องที่ยังไม่มี URL** จะเปิดหน้าตั้งค่าให้เองตอนเข้าใช้งานครั้งแรก
- **ขอเก็บข้อมูลถาวร:** แอปขอให้เบราว์เซอร์ไม่ล้างข้อมูลของแอปเมื่อพื้นที่เครื่องเต็ม
- **iPhone/Safari:** เว็บที่ไม่ได้เปิดเกิน 7 วันจะถูก Safari ล้างข้อมูล (รวมค่าที่จำไว้) แก้ได้โดยเพิ่มแอปไปยังหน้าจอโฮม แอปจะแจ้งเตือนในหน้าตั้งค่า
- **ตั้งค่าเครื่องใหม่ด้วย QR:** ที่แท็บ "เครื่องมือ" กด "สร้าง QR ตั้งค่าเครื่อง" ให้เครื่องใหม่สแกนหรือเปิดลิงก์ ระบบจะถามยืนยันก่อน แล้วจำค่าไว้ใช้งานได้ทันที (ส่งลิงก์ให้เฉพาะคนที่ไว้ใจ เพราะข้อมูลที่บันทึกจะถูกส่งไปยังฐานข้อมูลนั้น)
- **วิธีที่ง่ายที่สุดสำหรับทั้งองค์กร:** ฝัง URL ไว้ใน `DEFAULT_SCRIPT_URL` (ดูขั้นที่ 2) ทุกเครื่องจะใช้ได้ทันทีโดยไม่ต้องตั้งค่าเลย และแอปแบบฝัง URL จะไม่รับค่าจากลิงก์ตั้งค่า

## รายชื่อ Job

ช่อง Job No. มีรายการแนะนำขึ้นเองขณะพิมพ์ จากรายการที่เคยบันทึกในฐานข้อมูล (ทุกเครื่อง) รวมกับที่เครื่องนี้เพิ่งบันทึก

- แตะช่องโดยยังไม่พิมพ์ จะเห็น Job ล่าสุด พิมพ์ `206` ก็ขึ้น `V-20601`, `V-20602` (ไม่สนใจขีดและช่องว่าง)
- เลือก Job แล้วระบบ**ใส่สถานที่เดิมของ Job นั้นให้** (เฉพาะเมื่อช่องสถานที่ยังว่าง ไม่เขียนทับที่พิมพ์ไว้) พิมพ์ชื่อ Job ที่มีอยู่ครบแล้วออกจากช่องก็ใส่ให้เหมือนกัน
- ใช้ปุ่มลูกศรและ Enter เลือกได้บนคอมพิวเตอร์
- เมื่อเซิร์ฟเวอร์ล่มหรือออฟไลน์ ยังใช้รายการที่จำไว้ในเครื่องได้
- ต้องใช้ `Code.gs` v5.9 ขึ้นไป (คำสั่ง `getJobs`) รายชื่อถูกแคชที่เซิร์ฟเวอร์ 2 นาที และล้างทิ้งทุกครั้งที่มีการบันทึก/แก้ไข/ลบ

## ส่งออกรายงาน

ที่แท็บรายงานมีปุ่ม **Excel** และ **CSV**

**Excel (.xlsx)** ได้ไฟล์เดียว 2 ชีต
- **Activity Schedule:** ตารางแบบ "Activity Project Schedule" คือ ลำดับ / วันที่ / สถานที่ / Job แล้วแต่ละกิจกรรม (Arrival to Site, Safety Tool Box Talk, Work Permit Approve, Break, Close Permit, Arrival to Asia) แยกเป็นคอลัมน์ **D (กะเช้า)** และ **N (กะดึก)**
  - รายการที่ วันที่ + สถานที่ + Job เดียวกัน จะรวมเป็นแถวเดียว (เวลากะเช้าลง D กะดึกลง N) ถ้ากะเดียวกันมีหลายรายการ เช่น คนละคนรายงาน จะแยกเป็นแถวถัดไป ข้อมูลไม่ทับกัน
  - เรียงตามวันที่ จากเก่าไปใหม่ เวลาเป็นค่าเวลาจริงของ Excel (รูปแบบ hh:mm) วันที่เป็นวันที่จริง (เครื่องที่ตั้งค่าภาษาไทยจะแสดงเป็น พ.ศ. เอง) ตรึงหัวตาราง และตั้งหน้ากระดาษแนวนอนพอดีหน้าสำหรับพิมพ์
- **ข้อมูลทั้งหมด:** ข้อมูลละเอียดทีละรายการ (กำลังพล ผู้รายงาน เวลาบันทึก) มีตัวกรองในหัวตาราง ใช้ทำ Pivot ต่อได้

**CSV** ข้อมูลดิบทุกคอลัมน์ (เปิดภาษาไทยได้ถูกต้องใน Excel)

ทั้งสองปุ่มส่งออก **ทุกรายการของช่วงวันที่ที่เลือก** แม้หน้ารายงานจะแสดงแค่ 50 รายการ (ระบบดึงส่วนที่เหลือมาให้เอง) และใช้ตัวกรองค้นหา/กะที่ตั้งไว้ ถ้ามีเกิน 5,000 รายการ ให้เลือกช่วงวันที่ให้แคบลง ไฟล์ Excel สร้างในแอปโดยไม่พึ่งไลบรารีภายนอก ใช้งานได้แม้ออฟไลน์ (ถ้ารายการโหลดมาครบแล้ว)

**ชื่อกิจกรรม:** "Arrival to BEE" เปลี่ยนเป็น **"Arrival to Site"** ทั้งแอปแล้ว (ฟอร์ม รายงาน ไฟล์ส่งออก ไฟล์ Template นำเข้า) ส่วนหัวคอลัมน์ใน Sheet ข้อมูลยังเป็นชื่อเดิมภายในระบบ (`arr_bee`) เพื่อไม่ให้ข้อมูลเก่าที่บันทึกไว้เสียหาย

เปิดแอปบนจอกว้างตั้งแต่ 1024px ขึ้นไป (โน้ตบุ๊ก/คอมพิวเตอร์) จะเห็นแถบเมนูด้านข้างสีกรมท่าแทนแถบเมนูล่างของมือถือ และหน้า "รายงาน" จัดเป็น dashboard โดยอัตโนมัติ (กราฟอยู่ซ้าย สถิติอยู่ขวา) ไม่ต้องตั้งค่าอะไรเพิ่ม มือถือและแท็บเล็ตยังคงหน้าตาและการใช้งานแบบเดิมทุกประการ

## Login ด้วยรหัสพนักงาน

ช่อง "ชื่อผู้รายงาน" เข้าสู่ระบบด้วยรหัสพนักงานแทนการพิมพ์เองได้ โดยดึงชื่อจากแท็บ **People** ในชีต (คอลัมน์ A = รหัส, B = ชื่อ)

- **ฟีเจอร์นี้เปิดเองอัตโนมัติ** ก็ต่อเมื่อผู้ดูแลเริ่มใส่ "รหัส" ให้พนักงานอย่างน้อย 1 คนในแท็บ People ถ้ายังไม่ใส่รหัสเลย แอปจะทำงานแบบเดิมทุกประการ (พิมพ์ชื่อเอง มีรายชื่อแนะนำ) โดยไม่ต้องตั้งค่าอะไร
- เมื่อมีรหัสแล้ว เครื่องที่ยังไม่เคยเข้าสู่ระบบจะเห็นหน้า "เข้าสู่ระบบด้วยรหัสพนักงาน" ทันทีที่เปิดแอป กรอกรหัสครั้งเดียว ชื่อจะถูกจำไว้ในเครื่องนั้นและขึ้นให้อัตโนมัติทุกครั้งที่เปิดแอปในภายหลัง (ช่องชื่อจะล็อกไม่ให้แก้)
- มีลิงก์ **"เปลี่ยนผู้ใช้"** ใต้ช่องชื่อ และแถว "ผู้ใช้งาน" ในหน้าตั้งค่า สำหรับเครื่องที่ใช้ร่วมกันหลายคน (เช่น สลับกะ)
- พนักงานที่ยังไม่มีรหัสในระบบ กดลิงก์ **"พนักงานใหม่ยังไม่มีรหัส / พิมพ์ชื่อเอง"** เพื่อพิมพ์ชื่อเองได้ตามปกติ
- ใช้งานได้แม้ออฟไลน์ (เทียบกับรายชื่อที่แคชไว้ในเครื่อง เหมือนระบบแนะนำ Job)
- ตอนแก้ไขรายการเดิม ช่องชื่อจะกลับมาแก้ไขได้ชั่วคราว (แสดงชื่อเจ้าของรายการเดิม ไม่ใช่ผู้ใช้เครื่องนี้)
- บันทึกรหัสพนักงานลงคอลัมน์ `submitted_by` (รูปแบบ `emp:รหัส`) เพื่อย้อนดูได้ว่าใครเป็นคนบันทึกจริง แม้ไม่ได้เปิดโหมดบัญชีองค์กร
- รองรับชีตเดิมที่เคยมีแค่คอลัมน์ "ชื่อ" อย่างเดียว ระบบจะเติมคอลัมน์ "รหัส" ว่างไว้ด้านหน้าให้อัตโนมัติ ชื่อเดิมไม่หาย ผู้ดูแลแค่เติมรหัสทีหลังได้เลย

## จำนวนรายงานที่แสดง

ในแท็บรายงานเลือก **50 / 100 / 200 / ทั้งหมด** ได้ (ค่าเริ่มต้น 50 และจำค่าที่เลือกไว้)

- เซิร์ฟเวอร์ส่งมาเฉพาะจำนวนที่เลือก (ใหม่สุดก่อน) โดยอ่านเฉพาะคอลัมน์ที่จำเป็นก่อน จึงยังเร็วแม้ข้อมูลสะสมหลายพันแถว
- สถิติ กราฟ และตารางสรุปตาม Job คำนวณจากรายการที่โหลดมา เมื่อโหลดไม่ครบจะเปลี่ยนป้ายเป็น "รายการที่แสดง" และบอกจำนวนทั้งหมดในช่วงนั้นพร้อมปุ่ม "โหลดทั้งหมด"
- ปุ่ม Excel และ CSV ส่งออก**ทุกรายการของช่วงวันที่ที่เลือก** ไม่ขึ้นกับจำนวนที่แสดง (ใช้ตัวกรองค้นหา/กะที่ตั้งไว้ด้วย) ดูหัวข้อ "ส่งออกรายงาน"
- เลือก "ทั้งหมด": แสดงการ์ดทีละ 200 ใบ กด "แสดงเพิ่ม" เพื่อดูต่อ และเซิร์ฟเวอร์ส่งสูงสุด 5,000 รายการล่าสุด (ปรับที่ `REPORT_HARD_CAP` ใน `Code.gs`) ถ้ามีมากกว่านั้นให้เลือกช่วงวันที่

## การใช้งานพร้อมกันหลายคน

ออกแบบให้หลายคนบันทึก แก้ไข และดูรายงานพร้อมกันได้

**ฝั่ง Apps Script (`Code.gs`)**
- ช่วงที่ล็อกอยู่สั้นที่สุด: งานช้า (อัปโหลดรูป ตรวจรายการซ้ำ) ทำนอกล็อก ในล็อกทำเพียงเขียน 1 แถว และรอคิวได้นานสุด 28 วินาที
- กันบันทึกซ้ำด้วยรหัสรายการ: จำรหัสที่เพิ่งบันทึกไว้ 6 ชั่วโมงในแคช ทำให้แอปส่งซ้ำ/ลองใหม่ได้โดยไม่เกิดแถวซ้ำ
- การสร้างชีต เติมคอลัมน์ที่ขาด และสร้างโฟลเดอร์รูป ทำภายใต้ล็อก (ก่อนหน้านี้ถ้ามีหลายคนเข้ามาพร้อมกันหลัง Deploy เวอร์ชันใหม่ อาจเติมคอลัมน์ซ้ำ)
- ตรวจ Job ซ้ำ รายชื่อ Job และรายงาน อ่านเฉพาะคอลัมน์ที่จำเป็น ไม่อ่านทั้งชีต
- แก้ไขรายการพร้อมกัน: ถ้ามีคนอื่นแก้รายการเดียวกันไปก่อน จะแจ้งให้เลือก "เขียนทับ" หรือกลับไปดูข้อมูลล่าสุด

**ฝั่งแอป**
- ถ้าเซิร์ฟเวอร์ไม่ว่าง (ติดคิว หรือ Google ตอบ 429/503) แอปลองใหม่อัตโนมัติ 3 ครั้งแบบหน่วงเวลาเพิ่มขึ้นและสุ่ม ถ้ายังไม่ว่างจะเก็บรายการเข้าคิวในเครื่องและส่งให้ภายหลัง ข้อมูลไม่หาย
- การส่งรายการค้างเหลื่อมเวลาแต่ละเครื่อง ไม่รุมส่งพร้อมกันเมื่อเน็ตกลับมาหรือเซิร์ฟเวอร์ฟื้น
- หน้ารายงานรีเฟรชเองทุก ~90 วินาทีขณะเปิดอยู่ จึงเห็นรายการที่คนอื่นเพิ่งบันทึก (ไม่รีเฟรชเมื่อหน้าจอปิดหรือกำลังเปิดรายละเอียด)

**ข้อจำกัดของ Google ที่ควรรู้** (ตามเอกสาร [Apps Script quotas](https://developers.google.com/apps-script/guides/services/quotas)) ทำงานพร้อมกันได้ไม่เกิน **30 รายการต่อผู้ใช้** และ 1,000 ต่อสคริปต์ โควตาคิดต่อ "บัญชีเจ้าของสคริปต์" เมื่อตั้ง Execute as: Me พนักงานทุกคนจึงใช้โควตา 30 ก้อนเดียวกัน ถ้ามีคนกดบันทึกในวินาทีเดียวกันเกิน 30 คน ส่วนที่เกินจะถูกปฏิเสธชั่วคราว ซึ่งแอปรับมือด้วยการลองใหม่และเก็บเข้าคิวตามข้างต้น ตัวเลขโควตาของ Google เปลี่ยนได้ ตรวจที่หน้าเอกสารเป็นระยะ และดูการทำงานจริงได้ที่เมนู "การดำเนินการ" ใน Apps Script

## การกรอกข้อมูลและช่องเวลา

**ฟอร์มว่างทุกช่องโดยปริยาย** ไม่มีการเติมข้อมูลให้เอง ผู้กรอกต้องพิมพ์หรือเลือกเองทุกครั้ง (ชื่อผู้รายงาน, Job No., สถานที่, วันที่, กะ) และหลังบันทึกฟอร์มจะกลับมาว่างอีกครั้ง

- ช่อง Job No. อยู่ในการ์ด "งานและสถานที่" ปิดส่วนสถานที่ได้ที่ตั้งค่า แต่ช่อง Job จะแสดงเสมอ เพราะเป็นช่องบังคับ
- ใต้ช่องวันที่มีปุ่มลัด "วันนี้" และ "เมื่อวาน"
- ถ้าต้องการให้เครื่องใดเติมข้อมูลให้ ให้เปิด **ตั้งค่า > การกรอกข้อมูล > เติมข้อมูลให้อัตโนมัติ** (จำ Job/สถานที่ล่าสุด, ใส่วันที่และเลือกกะตามเวลาปัจจุบัน) การตั้งค่านี้มีผลเฉพาะเครื่องนั้น (ชื่อผู้รายงานไม่เกี่ยวกับสวิตช์นี้แล้ว ดูหัวข้อ "Login ด้วยรหัสพนักงาน")
- ร่างที่กรอกค้างไว้ (ยังไม่ได้ส่ง) ยังถูกกู้คืนเมื่อเปิดแอปใหม่ เพื่อไม่ให้งานที่กรอกไปแล้วหาย และจะไม่ขึ้นอีกหลังบันทึกสำเร็จ

**ช่องเวลาพิมพ์เองได้** พิมพ์ได้หลายแบบ ระบบแปลงเป็น HH:MM ให้เอง

| พิมพ์ | ได้ |
|---|---|
| `2012` หรือ `20:12` หรือ `20.12` | 20:12 |
| `0700` หรือ `700` หรือ `7:00` | 07:00 |
| `7` | 07:00 |

ถ้าพิมพ์แล้วอ่านไม่ออก ช่องจะขึ้นกรอบแดงและแจ้งวิธีพิมพ์ และจะบันทึกไม่ได้จนกว่าจะแก้ กด Enter เพื่อไปช่องเวลาถัดไป

**ปุ่มเลือกเวลาแบบฉลาด** ปรากฏใต้ช่องเวลาของขั้นตอนที่กำลังกรอก (ขั้นถัดไป หรือช่องที่แตะอยู่)

- **บ่อย:** เวลาที่เคยกรอกบ่อยในขั้นตอนนั้น ปัดเป็นช่วง 5 นาที เรียนรู้จากประวัติในเครื่องและแยกตามกะเช้า/กะดึก (เครื่องใหม่จะเรียนรู้จากรายงานที่โหลดมาจาก Sheet ด้วย)
- **+15น. / +30น. / +1ชม.:** ต่อจากเวลาของขั้นก่อนหน้า และถ้ามีประวัติพอ จะเสนอช่วงห่างที่มักเกิดขึ้นจริงให้ก่อน
- **ใกล้ตอนนี้ / -15น. / -30น.:** สำหรับขั้นแรก เผื่อกรณีลืมกดตอนถึงหน้างาน
- **−5 / +5:** ปรับเวลาที่กรอกแล้วทีละ 5 นาที
- ระบบจะไม่เสนอเวลาที่ย้อนก่อนขั้นตอนก่อนหน้า และกะดึกที่ข้ามเที่ยงคืนคำนวณถูกต้อง

## สถานะเซิร์ฟเวอร์ เสียงแจ้งเตือน และภาพพื้นหลัง

**สถานะการเชื่อมต่อเซิร์ฟเวอร์** แสดงเป็นป้ายใต้ชื่อแอปที่ header แตะป้ายเพื่อดูรายละเอียด (เวลาตอบกลับ, ไฟล์/ชีตที่บันทึก, จำนวนรายการรอส่ง)

| ป้าย | ความหมาย |
|---|---|
| เชื่อมต่อแล้ว (จุดเขียว) | ติดต่อ Apps Script ได้ |
| ตอบช้า (จุดเหลือง) | ติดต่อได้ แต่ตอบนานเกิน 4 วินาที |
| เชื่อมต่อไม่ได้ (จุดแดง) | มีอินเทอร์เน็ต แต่ Apps Script ไม่ตอบหรือตอบผิดปกติ |
| ออฟไลน์ (จุดเทา) | เครื่องไม่มีอินเทอร์เน็ต |
| ยังไม่ตั้งค่า | ยังไม่มี URL ของ Apps Script |

- สถานะอัปเดตเองทุกครั้งที่ส่ง/โหลดข้อมูล และตรวจเพิ่มทุก 2 นาทีขณะเปิดแอป ด้วยคำสั่ง `ping` แบบเบาที่ไม่เปิด Sheet จึงใช้โควตาของ Apps Script น้อยมาก
- ต้องใช้ `Code.gs` เวอร์ชัน v5.7 ขึ้นไป ถ้ายังเป็นเวอร์ชันเก่า ป้ายจะยังขึ้นว่าเชื่อมต่อแล้ว แต่ในหน้ารายละเอียดจะแจ้งให้อัปเดต

**เสียงแจ้งเตือน** (ตั้งค่า > เสียงและการแสดงผล) สังเคราะห์เสียงด้วยเบราว์เซอร์ ไม่ต้องมีไฟล์เสียง และใช้ได้ตอนออฟไลน์

- เสียงไล่ขึ้น 3 โน้ต = บันทึกสำเร็จ / ติ๊ก-ติ๊ก = เก็บไว้ส่งทีหลัง / ต่ำ 2 ครั้ง = ผิดพลาด / บี๊บ 3 ครั้ง = เตือนลืมกรอก
- เลือกระดับเสียงเบา/กลาง/ดังได้ มีปุ่มทดสอบเสียง
- มือถือต้องแตะหน้าจอสักครั้งหลังเปิดแอป เบราว์เซอร์จึงจะอนุญาตให้เล่นเสียง และบน iPhone สวิตช์ปิดเสียง (Silent) จะปิดเสียงนี้ด้วย

**ภาพพื้นหลัง** มีแบนเนอร์ภาพโรงงานและคลื่นน้ำด้านบนหน้าบันทึก และภาพเมืองอุตสาหกรรมจาง ๆ ด้านหลังทุกหน้า

- ผู้ใช้ปิดได้ที่ ตั้งค่า > ภาพพื้นหลัง และโหมดถุงมือจะปิดภาพให้อัตโนมัติเพื่อให้อ่านง่ายกลางแดด
- ใช้รูปของหน่วยงานเอง: วางไฟล์ภาพ (เช่น `bg.jpg`) ไว้ในโฟลเดอร์เดียวกับ `index.html` แล้วแก้ `BG_IMAGE_URL` ใน `config.js` เป็น `'bg.jpg'` ระบบจะซ้อนฟิล์มสีขาวบาง ๆ ให้ตัวหนังสืออ่านง่าย แนะนำภาพขนาดไม่เกิน 300 KB

## ขั้นที่ 2: ฝัง URL ลงในหน้าเว็บ

เปิด `config.js` ค้นหา (Ctrl+F) คำว่า `DEFAULT_SCRIPT_URL` แล้ววาง URL จากขั้นที่ 1 ระหว่างเครื่องหมายคำพูด:

```js
const DEFAULT_SCRIPT_URL = 'https://script.google.com/macros/s/AKfy..../exec';
```

เมื่อฝัง URL แล้ว:

- ทุกเครื่องเชื่อมกับ Sheet ได้ทันที พนักงานไม่ต้องตั้งค่าอะไร
- หน้าตั้งค่าจะ**ไม่แสดงช่อง URL** จึงไม่มีใครแก้ผิดได้
- URL ที่ฝังจะ**ชนะค่าเก่า**ที่เคยบันทึกค้างในเครื่อง (กันกรณีเครื่องยังชี้ไป Deployment เก่า)
- ถ้าฝัง URL ผิดรูปแบบ (เช่น ลงท้ายด้วย `/dev`) แอปจะแจ้งเตือนทันทีที่เปิด และปุ่ม "ทดสอบการเชื่อมต่อ" จะบอกสาเหตุ

ถ้าเว้นว่างไว้ ผู้ใช้แต่ละคนต้องวาง URL เองที่ปุ่มตั้งค่า

## ขั้นที่ 3: เผยแพร่บน GitHub Pages

1. สร้าง repository ใหม่บน GitHub เช่น `field-app` (เลือก Public)
2. อัปโหลดไฟล์ทั้งหมดในโฟลเดอร์นี้ขึ้นไปที่ root ของ repo
   (บนเว็บ: **Add file > Upload files** แล้วลากทั้งโฟลเดอร์ลงไป)
   > ไฟล์ `.nojekyll` เป็นไฟล์ซ่อน ถ้าลากแล้วไม่ติดไป ให้สร้างเองด้วย **Add file > Create new file** ตั้งชื่อ `.nojekyll` เว้นเนื้อหาว่าง
3. ไปที่ **Settings > Pages**
   - Source: **Deploy from a branch**
   - Branch: **main** / **(root)** แล้วกด Save
4. รอ 1–2 นาที แอปจะอยู่ที่ `https://<ชื่อผู้ใช้>.github.io/field-app/`

### อัปเดตหน้าเว็บภายหลัง

แก้ไฟล์แล้วอัปโหลดทับ และ **เปลี่ยนเลขเวอร์ชันใน `sw.js`** ทุกครั้ง เช่น

```js
const CACHE = 'field-app-v5-3';
```

ไม่อย่างนั้นเครื่องที่ติดตั้งแอปไว้อาจยังใช้ไฟล์เก่าอยู่

## ขั้นที่ 4 (ไม่บังคับ): สรุปรายวันเข้ากลุ่ม LINE

2. ตั้ง **Webhook URL** เป็น Web app URL จากขั้นที่ 1 เปิด *Use webhook* และ *Allow bot to join group chats*
3. เชิญบอทเข้ากลุ่ม แล้วพิมพ์ `ลงทะเบียน` (หรือ `ลงทะเบียน <LINE_REGISTER_CODE>`)
4. กลับไปที่ Apps Script แล้ว Run ฟังก์ชัน `setupDailySummaryTrigger` หนึ่งครั้ง
   ระบบจะส่งสรุปทุกวันเวลา 19:00 และพิมพ์ `สรุป` ในกลุ่มเพื่อดูได้ทุกเมื่อ

## หมายเหตุด้านความปลอดภัย

- `Code.gs` ไม่มีรหัสลับใด ๆ อยู่ในโค้ด รหัสทั้งหมดเก็บใน Script properties จึงเก็บไฟล์นี้ใน repo สาธารณะได้
- Web app URL เป็นข้อมูลที่ใครมีลิงก์ก็ส่งข้อมูลเข้ามาได้ ถ้าต้องการจำกัดการแก้ไข/ลบ ให้ตั้ง `ADMIN_PINS` (ดู `ADMIN.md`)
- รูปถ่ายถูกแชร์แบบ "ทุกคนที่มีลิงก์ดูได้" เพื่อให้แอปแสดงรูปตัวอย่างได้
  ถ้าไม่ต้องการ ให้แก้ `PHOTO_PUBLIC_LINK: false` ใน `Code.gs`

## แก้ปัญหาเบื้องต้น

| อาการ | วิธีแก้ |
|---|---|
| ส่งข้อมูลแล้วขึ้น "เชื่อมต่อเซิร์ฟเวอร์ไม่ได้" | ตรวจว่า Deploy เป็น *Anyone* และ URL ลงท้ายด้วย `/exec` |
| แก้โค้ด Apps Script แล้วไม่มีผล | ต้อง Deploy เป็น *New version* ทุกครั้ง |
| หน้าเว็บไม่อัปเดตบนมือถือ | เปลี่ยนเลข `CACHE` ใน `sw.js` แล้วอัปโหลดใหม่ ปิดแล้วเปิดแอปสองครั้ง |
| ไม่มีปุ่มติดตั้งแอป | ต้องเปิดผ่าน `https://` (GitHub Pages ใช้ได้) และบน iPhone ให้กด แชร์ > เพิ่มไปยังหน้าจอโฮม |
